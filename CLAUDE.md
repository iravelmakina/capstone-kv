# CLAUDE.md

KSE Cloud Architectures 2026/27 capstone: a small DynamoDB-like key-value store, built
over five milestones in the **AWS Academy sandbox**.
The full course brief (all milestones) is `docs/course/capstone-brief.md`. **The brief
wins** over anything here. The M1 plan is the OpenSpec change `m1-infra-setup`.

## Integrity rules (breaking them counts as plagiarism)

1. **Spec before code.** No IaC or code for a change until its OpenSpec change and ADRs
   are `Accepted`, the author has approved them in chat, and they are committed.
2. **Separate commits** for spec and code. Never edit an accepted ADR to match code; write
   a new ADR that supersedes it.
3. **Explain every generated line** to the author before committing it.
4. **Log every agent interaction** in `AGENT_WORKLOG.md`. Never present AI output as hand-written.
5. **The AI design review comes from a fresh session** with no project context.

## AWS rules

- Milestones run in AWS Academy: profile `academy`, role `voclabs`, **us-east-1**.
  Credentials expire each lab session; the author refreshes them. Never write credentials
  anywhere, including the repo.
- The brief's "LabRole" is a generic name (lecturer): here it's `voclabs` (our role) and
  `Inventory-App-Role` (the instance role).
- The lab account also holds the AWS capstone's own resources ("Project VPC", a lab
  stack). Prefix ours with `velmakina-`, never touch theirs, never press **Reset**.
- Profile `kse-lab` on this machine is a shared course account, not the milestone
  environment. Never use it.
- Run `aws sts get-caller-identity --profile academy` before any session's first call.
- Ask before any write call (`deploy`, `delete-stack`, a real `create-*` …). Read-only
  calls and `--dry-run` are fine.
- Committed evidence: replace account IDs with `<ACCOUNT_ID>`.
- Never deploy `infra/iam-readonly.yaml`; only lint it.
- Remote: personal GitHub (`iravelmakina`).
