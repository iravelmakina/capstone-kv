===== [S3] two problems on the monitor and the nodes, found through the tunnels =====
1. Grafana restarted in a loop. `make release` packed monitoring/ with macOS tar, which
   adds AppleDouble files (`._name`); Grafana read `._dashboards.yml` as provisioning and
   exited. docker compose mounts the folder directly, so local runs never saw it. Fixed on
   the monitor through SSM (the `._*` files deleted, author approved), then in code
   (f20cfbc): `COPYFILE_DISABLE=1 tar --exclude='._*'`, and monitor-boot.sh deletes any
   `._*` after extracting.

   are `./alloy.alloy`; GNU tar found nothing and Alloy never started. Fixed in d8f41f62
   (extract `./alloy.alloy`; `tar --no-xattrs` so macOS attributes don't become pax
   headers). New release d8f41f62a6bc uploaded and the stack updated (author approved);
   the user data change updated the instances in place.

===== Open after the lab =====
- D2 against ADR-0026 (above): one node held both leaders, and the closed-loop client
  turned 14.7 s of 503 into ≈ 0.93% of an hour's requests. ADR-0030 (proposed) supersedes
  ADR-0026's availability value; the author decides. D1' shows the other side of it: a
  stopped follower node costs nothing.
- The burn-rate alerts fire on a handful of errors at almost no traffic (S5): a
  minimum-traffic guard is a design change (ADR-0029), for the author to decide.
- Prometheus and Loki lose their data on a lab restart (R1).
- smoke-replica can't pass under write load (D1'); fine for its purpose, worth a comment.
