===== [S3] two problems on the monitor and the nodes, found through the tunnels =====
1. Grafana restarted in a loop. `make release` packed monitoring/ with macOS tar, which
   adds AppleDouble files (`._name`); Grafana read `._dashboards.yml` as provisioning and
   exited. docker compose mounts the folder directly, so local runs never saw it. Fixed on
   the monitor through SSM (the `._*` files deleted, author approved), then in code
   (f20cfbc): `COPYFILE_DISABLE=1 tar --exclude='._*'`, and monitor-boot.sh deletes any
   `._*` after extracting.
2. Loki had no logs. node-boot.sh extracted `alloy.alloy` from the archive, whose members
   are `./alloy.alloy`; GNU tar found nothing and Alloy never started. Fixed in d8f41f62
   (extract `./alloy.alloy`; `tar --no-xattrs` so macOS attributes don't become pax
   headers). New release d8f41f62a6bc uploaded and the stack updated (author approved);
   the user data change updated the instances in place.

# What this shows:
# - Both leaders were on the stopped node. Node A registered late at start (S2), so 1b won
#   shard-1's first election instead of 1a (ADR-0020 expects 1a and 2b). Both shards
#   stopped taking writes for 14.7 s (INSERT_ERROR span), and both promoted (epoch 2).
# - The stop landed in the load phase (inserts only). A 503 comes back in ~5 ms against
#   ~23 ms for a committed write, so the 16-thread client sent 3417 failing writes per
#   second: 50320 errors in 14.7 s, about as many as the whole phase's successful inserts.
# - No read 5xx (only write series in the 5xx query). The 47887 READ_ERROR are, most
#   likely, reads of keys whose insert failed (404 counts as an error in go-ycsb); not
#   checked key by key.
# - Read p99 of shard-2 over those 2 minutes was 19.8 ms, above the 15 ms SLO; read max
#   1.01 s, not the 3 s client timeout ADR-0026 feared. Write p99 58-59 ms, under 60 ms.
# - Against ADR-0026: it assumed one leader change costs ~20 s of 503 on one shard's
#   writes, ≈ 0.14% of an hour's requests. Here one node held both leaders and the
#   closed-loop client multiplied the failures: ~50k 5xx in about 1.05 M requests (≈ 4.8%)
#   spent the hour's budget at once. Whether to supersede ADR-0026 (or ADR-0020's leader
#   placement) is the author's decision; not done here.
