===== [73] 73-simulate-scoped-view-policy (2026-11-06) =====
# velmakina-view split by what AWS lets us scope: list/describe calls that accept only "*"
# in one statement; S3 bucket settings, IAM Get and DynamoDB DescribeTable limited to
# velmakina-* resources. cfn-lint: no findings.
# !Sub resolved with example values (account 123456789012) to run the simulator.
$ aws iam simulate-custom-policy --policy-input-list <ViewPolicy> <DenyDataPolicy> --action-names <action> [--resource-arns <one ARN per call>]

# scoped statements: our resource vs someone else's
s3:GetBucketPolicy	arn:aws:s3:::velmakina-builds	allowed
s3:GetBucketPolicy	arn:aws:s3:::someone-elses-bucket	implicitDeny
s3:GetBucketVersioning	arn:aws:s3:::velmakina-builds	allowed
s3:GetBucketVersioning	arn:aws:s3:::someone-elses-bucket	implicitDeny
iam:GetRole	arn:aws:iam::123456789012:role/velmakina-readonly	allowed
iam:GetRole	arn:aws:iam::123456789012:role/voclabs	implicitDeny
iam:GetPolicy	arn:aws:iam::123456789012:policy/velmakina-view	allowed
iam:GetPolicy	arn:aws:iam::123456789012:policy/other-policy	implicitDeny
dynamodb:DescribeTable	arn:aws:dynamodb:us-east-1:123456789012:table/velmakina-kv	allowed
dynamodb:DescribeTable	arn:aws:dynamodb:us-east-1:123456789012:table/other-table	implicitDeny
# account-wide statement (AWS accepts only *)
ec2:DescribeVpcs	*	allowed
s3:ListAllMyBuckets	*	allowed
dynamodb:ListTables	arn:aws:dynamodb:${Region}:${Account}:table/*	allowed
iam:ListRoles	arn:aws:iam::<ACCOUNT_ID>:role/	allowed
# deny-data still wins, even on our own resources
s3:GetObject	arn:aws:s3:::velmakina-builds/key	explicitDeny
dynamodb:GetItem	arn:aws:dynamodb:us-east-1:123456789012:table/velmakina-kv	explicitDeny
ec2:DescribeLaunchTemplateVersions	*	explicitDeny
ec2:DescribeInstanceAttribute	*	explicitDeny
# writes
s3:PutBucketPolicy	arn:aws:s3:::velmakina-builds	implicitDeny
ec2:RunInstances	*	implicitDeny
iam:CreateRole	*	implicitDeny
